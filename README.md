# infra-monitoring-project

Учебный DevOps-проект, демонстрирующий навыки работы с Bash, Git, Docker, Docker Compose и CI/CD. 
Включает в себя скрипты мониторинга API, анализа логов и контейнеризированную среду для развертывания сервиса.

## Требования

Для работы с проектом вам понадобятся:
- **Git** для клонирования репозитория
- **Bash** или Git Bash / WSL для Windows
- **Docker** и **Docker Compose** для запуска контейнеров
- **Wireshark** для захвата и анализа сетевого трафика

## Структура проекта

- `check_api.sh` — Bash-скрипт для проверки доступности API (ожидает код 200).
- `analyze_logs.sh` — Bash-скрипт для генерации и анализа логов (топ IP, ошибки 4xx/5xx).
- `docker-compose.yml` — конфигурация для запуска сервиса API и Nginx-прокси.
- `nginx.conf` — конфигурация Nginx для проксирования запросов на API.
- `.github/workflows/ci.yml` — пайплайн GitHub Actions для проверки синтаксиса скриптов.

## Этап 1. Git Workflow и организация проекта
Проект размещен в публичном репозитории GitHub. 
- Основная ветка: `main` (защищена).
- Рабочая ветка: `feature/monitoring` (в ней велась вся разработка).
- Создан файл `.gitignore`, исключающий логи (`*.log`), временные файлы (`*.tmp`) и артефакты сборки (`/build/`).
- В конце работы создан Pull Request из `feature/monitoring` в `main` с подробным описанием изменений.

## Этап 2. Анализ сетевого трафика
В рамках задания был установлен Wireshark и произведен захват сетевого трафика.
- Выполнены HTTP-запросы к публичному API (`http://api.zippopotam.us/us/90210`, `http://jsonplaceholder.typicode.com/posts/1`) с помощью `curl`.
- Трафик отфильтрован по протоколу HTTP.
- Дамп трафика сохранен в формате `.pcapng` и приложен к отчету.
- В отчете также указаны IP-адреса участников обмена, использованные HTTP-методы (GET, POST) и коды ответов сервера.

## Этап 3. Bash-скрипты для мониторинга и анализа
Оба скрипта сделаны исполняемыми (`chmod +x`).

### 1. Скрипт мониторинга API (`check_api.sh`)
Принимает URL API как аргумент командной строки, делает HTTP-запрос через `curl`, проверяет код ответа (ожидается 200). Возвращает код возврата 0 при успехе, 1 при ошибке.
**Пример работы с валидным URL:**
./check_api.sh https://httpbin.org/status/200
# Вывод: API доступен
**Пример работы с невалидным URL:**
./check_api.sh https://httpbin.org/status/404
# Вывод: API недоступен, код ответа: 404

### 2.  Скрипторинга API (`check_api.sh`)
Генерирует тестовый файл access.log (минимум 300 строк) с заданным форматом. С помощью grep, awk, sort, uniq и регулярных выражений выводит:
- Общее количество запросов.
- Топ-3 IP-адреса с наибольшим числом запросов.
- Количество запросов с кодами 4xx и 5xx.
Запуск скрипта:
./analyze_logs.sh

## Этап 4. Docker Compose для стека мониторинга
В корне проекта создан файл docker-compose.yml, описывающий два сервиса, связанных внутренней сетью Docker:
- api: использует образ hashicorp/http-echo, возвращает текст “Monitoring Service Active” на порту 8080.
- proxy: использует образ nginx:alpine, который проксирует запросы с порта 80 на порт 8080 сервиса api.
Инструкция по проверке:
docker-compose up -d
curl.exe http://localhost
# Ожидаемый вывод: Monitoring Service Active
Скриншот работы команд приложен к отчету.

## Этап 5. CI/CD Pipeline (GitHub Actions)
В директории .github/workflows/ создан файл ci.yml. Пайплайн настроен на запуск при создании Pull Request и выполняет следующие шаги:
1.	Проверка синтаксиса Bash-скриптов: bash -n check_api.sh и bash -n analyze_logs.sh.
2.	Тестирование скрипта мониторинга: запуск check_api.sh https://httpbin.org/status/200 с ожиданием кода возврата 0.
Пайплайн успешно пройден (зеленая галка в GitHub). Скриншот приложен к отчету.

## Этап 6. SSH и SCP (Деплой на удаленный сервер)
Для безопасной передачи файлов проекта на удалённый сервер используются протоколы SSH и SCP.
### 1. Генерация SSH-ключей
ssh-keygen -t ed25519 -C "your_email@example.com"
### 2. Копирование публичного ключа на сервер
ssh-copy-id -i ~/.ssh/id_ed25519.pub user@remote-server
### 3. Передача архива проекта на сервер
Вариант с использованием SCP:
# Создание архива
tar -czf project.tar.gz .
# Копирование на сервер
scp project.tar.gz user@remote-server:/path/to/deploy/

Вариант с использованием tar + ssh (без промежуточного файла):
tar -czf - . | ssh user@remote-server "tar -xzf - -C /path/to/deploy/"

#Пример команд для деплоя
Подключение к серверу, распаковка (если использовался SCP) и запуск контейнеров:
ssh user@remote-server
cd /path/to/deploy/
tar -xzf project.tar.gz
docker-compose up -d
